How column dependencies affect query performance

The independence assumption: Without extended statistics, PostgreSQL estimates the selectivity of WHERE a = 1 AND b = 2 as sel(a) * sel(b) — assuming columns are independent.

When columns are correlated: If user_id=123 always has status='active', the actual cardinality is much lower than the independent estimate. The planner overestimates rows, choosing nested loops when hash join is 100x faster.

The fix: CREATE STATISTICS tells PostgreSQL to track the actual joint distribution, producing accurate estimates and dramatically better plans.
