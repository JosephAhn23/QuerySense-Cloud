Educational multi-column index design with cardinality-based ordering. Explains why columns should be ordered, not just what to create. Based on pganalyze Efficient Search p.17-18.

Multi-Column Index Ordering Principles

  1. Equality columns first (WHERE col = value) — narrows B-tree most efficiently
  2. Higher cardinality first among equality columns — more distinct values = more selective
  3. Range columns next (>, <, BETWEEN) — only one range column per index is efficient
  4. ORDER BY columns last — enables sort elimination (no separate Sort step)
  5. INCLUDE for covering — avoid heap fetches entirely with index-only scans
